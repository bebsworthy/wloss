### Projection behavior analysis and proposal (2026-09-18; implementation pending)

Owner reports layout jumping and incorrectly hidden maintenance/opposing-direction charts. Verified causes: IntakeProjection removes its 166dp canvas and 6dp gap when forecast is null; the source chip also disappears and changes header metrics. ViewModel explicitly discards bands unless (goal−weight)×(intake−maintenance)>0, excluding maintenance and opposite-direction scenarios. ForecastEngine is a goal-arrival engine: it selects loss/gain from the goal, returns empty trajectories when goal equals current weight, stops at goal, and flattens outer bands when its goal-oriented pace is non-positive. Simply removing the UI conditional is insufficient. Recalculation also emits an intermediate null forecast. The conditional Use suggestion row is another layout-shift source.

Show loss, gain and maintenance paths regardless of the selected goal; continue beyond target crossings for the hypothetical unchanged intake. Reuse production model equations and provenance, and validate continuity/uncertainty on both sides of zero. Separate goal-plan recommendation eligibility from whether a scenario can be computed; opposite direction, maintenance or absence of a crossing are not unavailable states. Missing inputs, invalid edit text or genuinely unsupported model inputs get an in-place status, not a collapsing card or fabricated curve. Publish recalculation atomically and give suggestion restore a stable existing-row slot. Verify loss/maintenance/gain objectives crossed with negative/zero/positive adjustments, target crossings, invalid text and weekly allocations, including slider drags with unchanged control bounds.
