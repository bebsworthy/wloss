  1. 9Confidence ring draws clockwise in 400 ms around the kcal number (motion table). Color boundaries are frozen: green ≥ 0.7 = accent, amber 0.4–0.7 = held, grey < 0.4 = text-secondary. This scan is 0.74 → green.

DB-matched items keep “DB-verified” — only grams were estimated.
  3. 11Item chips carry per-item kcal + per-item confidence (0.88 green · 0.61 amber — both boundary cases on one card). Tap → swap / portion / “not this”; nothing auto-commits, 100 % editable before save.
  4. 12Portion slider: detents every 5 g, 5 ms ticks. Crossing a clamp rail fires a double-sided bump, the number flashes its rail glyph, and a 900 ms one-time tooltip (“capped at a physical maximum — tap to override”) appears — once per food class, never again. Sanity rails (≤ 9 kcal/g fats, ≤ 4 cooked starches, mass × density ceiling) run under every number: the 27M-kcal candy bar cannot render, even as a glitch; a rail hit also downgrades confidence and shows its marker.
  5. 13Plate-level hint field — the text-steerable re-estimate. No word limit (SnapCalorie’s truncation is a named anti-pattern); numbers morph with a 250 ms digit-roll and changed items re-spring.
  6. 14Save is live immediately — the two-tap happy path ends here. A failed rescan is a 2-frame 8 px horizontal shake, no red — mistakes are data, urgency is never hue. Open question (F02 §10): the no-ARCore device tier — portion falls back to reference-object heuristics vs. user-confirmed grams; this mock assumes depth present.

Self-review — design bar & spec checklist (flow 02)

Design bar
  1. Provenance chips on every number — plate kcal (AI-estimated · on-device), per-item conf chips, DB rows (USDA FDC # / OFF cache), label entry (measured · label), chai (user-entered), diary row + ring (adaptive · check-in Sep 8). None missing. ✓
  2. Tone: numbers never judgment — “1,277 left”, “696 left”, “rough guess — adjust what’s wrong” (the app indicts its own estimate, never the eater). Banned copy audit clean: no “that’s a lot of calories”, no cheat/bad/guilt anywhere. ✓
  3. No red exists — errors are a 2-frame 8 px shake (annotated on Rescan/barcode-miss); the strongest state color on any screen is amber; low confidence reads as texture (irregular stroke), not alarm. ✓
  4. R-U7 — n/a on this surface (no Archive/Digestion naming decision touches it), but checked: nav labels in the save-arc mock use the frozen names; diary and hint copy contain no taboo words. ✓
  5. R-U15 manual paths visible everywhere — five equal ladder chips at viewfinder rest; “type it instead” + search survive inside the offline sheet; every fallback (barcode miss → label OCR → manual fields; recognition fail → chips stay editable) lands on manual without loss. ✓
  6. Local-first — no server spinner in any state; the analyzing copy names the on-device pipeline; offline is a non-state with an identical pipeline; the only servers named are OFF/USDA. ✓
  7. Discretion by default — cloud requires per-capability consent at call time, EXIF-stripped downscaled pixels, F12 receipt; photo discarded at save (R-U14) stated once on the surface, never nagged. ✓
  8. Density — the result card stacks 6 decisions (ring, provenance, 3 item chips, slider, hint, save) in one sheet with zero decoration; whitespace only around the confidence ring, the moment of decision. ✓
