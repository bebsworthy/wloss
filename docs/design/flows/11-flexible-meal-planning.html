Flow & design handoff

Day agenda → edit portions directly, add several items in one sheet, using the + beside its heading. All meals remain visible, including empty entries. The agenda is the landing screen even when the user never plans. Week/day navigation is permanent; there is no onboarding, travel mode, flexible-state editor, or plan-completion requirement.

“Suggest meals” opens a bottom sheet from the toolbar. Preview fills only selected empty entries. Suggested rows remain drafts across date navigation until Add or Discard. Existing meals are preserved. Demo today is Monday 21 September 2026; past/today additions default to Eaten; future additions remain Planned.

HTML interaction study, not Compose or an official Material Web implementation. Production maps to Scaffold, TopAppBar, ListItem, Button/TextButton, Checkbox, DateRangePicker, OutlinedTextField and Snackbar. Native HTML controls carry keyboard semantics. Target 48 px minimum, local Inter, shared WLO colors, visible focus and reduced-motion support.

Nutrition and existing recipes are prepared fixtures; there are no external calls or app data writes. Meals contain multiple independent foods, drinks and recipe portions. Inline portions, removal, add-many sheet, optional calories and a single meal-level + action are interactive; photo/voice capture and real food search are outside this study.
