Self-review — design bar & spec checklist (flow 08)

Design bar
  • Provenance inline (R-D12, amended): the adjusted load wears “all sets reached 8 at RPE 8” + ⓘ; e1RM wears “Epley, ≥ 3 sets” + ⓘ; expenditure wears its inputs + ⓘ. Headers name things (“Today’s session”, “Lower A”) and carry no numbers’ provenance.
  • No self-congratulation (R-D15): the PR is a number moving old → new; the summary is a receipt; nothing says fast, easy, or amazing. No confetti — per spec.
  • No verdicts: a swap “keeps today’s stimulus”; nothing can be missed here. No “leg day” scolding, no streak pressure. Expenditure never becomes a target — stated once, as data practice.
  • Tokens: dark theme, accent for state only, amber for the honest-mismatch chip; red does not exist. kg throughout (R-D10); tnum on every changing numeral.
  • Gym ergonomics: 56 dp set rows, confirm in the thumb arc, rest controls at top-right where the phone props; nav dropped while live.
  • Location stays home: the route trace is drawn from on-device coordinates; it never appears in notifications and is excluded from share receipts unless opted in per share.
Spec coverage (F05 §4)
  • Happy path — preview → prefilled sets → rest ring → finish → summary: mocks 1, 2, 5. No keyboard in the common case ✓ (mock 3 shows the only exception: deliberate load change).
  • Plate mismatch — honest “Closest possible” chip, inventory per profile ✓ mock 3.
  • Substitutions — long-press, muscle ∩ equipment ranking, travel re-derivation ✓ mock 4.
  • Set-type flows — warm-up lighter style ✓ (ramp calculator cited); failure/drop badges and AMRAP prompt specified in pins, not drawn.
  • Data-quality gating — e1RM’s ≥ 3-sets gate shown inline; expenditure hidden without bodyweight (persona has F06 data) is a caption note.
  • Explainability — the preview’s adjustment sentence is the readable rule engine; cap ≤ 10 %/session in pin 1.
  • Cardio parity (R-S11 as amended) — live GPS/HR session (mock 6): time · distance · pace · zone at a glance, zero mandatory input outdoors, one field on the erg; manual fallback and Health-Connect imports on one week timeline (mock 7); pace/zone/GPS formulas worn inline per the provenance rule.
Not shown here (deliberate)
  • Supersets/circuits queue animation; template authoring/versioning UI (View template only); warm-up ramp calculator face; logbook table, e1RM/volume charts, PR timeline, muscle heatmap — stats surfaces belong with Insights’ flow when that is mocked; recovery body-map and plateau dialogue are [v1.x].
  • Structured cardio workouts (guided intervals) are [future]; per-split tables and pace-curve charts belong with the stats surfaces when those are mocked.
  • Widget start/pause and notification resurrector: cited in wireframe 1 / mock 2, not drawn.

  • “Update bodyweight” writes F06 exactly as flow 04’s weigh-in does — one bridge, explicit, user-tapped.
  • Cardio sessions hand F07 the same context-only expenditure as lifts; steps bypass logging entirely and reach the Hub’s step ring and the engine’s activity term straight from Health Connect.
