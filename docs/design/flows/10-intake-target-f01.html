Design handoff

Compose uses Scaffold, TopAppBar, SingleChoiceSegmentedButtonRow, Slider, OutlinedTextField, ListItem, RadioButton and Button. The HTML uses a native range input for the slider study. Slider stops use 25 kcal increments with zero centered; its symmetric range expands for typed values outside the initial range. Calorie floor and goal-direction restrictions do not block manual saving in this owner-requested mockup revision; exact numeric entry is preserved. Both modes keep the slider visible. Intake mode translates the scale to total kcal/day, with estimated maintenance at the center. The same 25 kcal adjustment stops and thumb position persist across modes. Inline expandable sections preserve draft input. Weight goal provides no chosen pace. Missing profile information is collected only when required for estimation; eligibility and production nutrition validation use the shared contract. This prototype demonstrates an already-complete profile, numeric validation and explicit Save. Projection uses a widening band without a point-date promise. Production must render the shared forecast engine’s supported output; the demo equation and visual bounds are not production policy. An unavailable projection does not block manual Save. Back cancels the draft; reopening restores the saved target. Large content scrolls inside the phone, with Save kept available.
