Scope, interaction map & native handoff

First pass: agenda → Add to dinner → create with AI / import / write → shared editable review → save / save & add. Library → search / favorites → details → variation / notes / cook. Unknown yield can be saved; portion-dependent actions stay held. Local draft and cooking session recovery, ingredient correction and text/row editing are interactive.

Visual baseline: WLO-0156 daily agenda, Inter from the local design system, shared dark/teal semantic tokens and dense divider-separated rows. The Recipes toolbar entry is a proposed extension; the existing four navigation destinations are retained. Nested screens hide the navigation bar. This HTML study maps to native M3 Scaffold, TopAppBar, ListItem, Checkbox, OutlinedTextField, Button, FilterChip, ModalBottomSheet and Snackbar; it is not a Compose build or official Material Web implementation.

AI produces one fixed dish in this pass; “use lentils” demonstrates one refinement. Website import loads a sample with incomplete yield; pasted text remains editable. Matching is a small local fixture vocabulary, with unknown lines held. Multi-recipe meals, counted sub-recipes, nested links, timers, cloud consent setup and large-window app layouts are outside this first mockup. The responsive workbench is review tooling, not a tablet app proposal.

Validation and screenshots: WLO-0166 review evidence. Nothing is written to the Android app or sent to an external service.
